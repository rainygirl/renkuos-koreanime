## Why gcc2 on 32-bit x86

The add-on is loaded by input_server, and on an x86_gcc2 hybrid input_server
is a gcc2 program; a gcc13 (x86 secondary) add-on cannot be loaded by it.
So the x86_gcc2 package is a primary-architecture package, `koreanime`, not
`koreanime_x86` -- an exception to pkgman-repo's "x86 apps use the secondary
toolchain" rule, for the same reason screensavers are. The sources are
C++98 for gcc 2.95.

## How it talks to input_server

- `Filter()` gets every key. Composition messages (B_INPUT_METHOD_EVENT) go
  out through `outList` together with a copy of the key when the key is to
  go on as well: input_server puts that list in the key's place, in order.
  `EnqueueMessage()` appends to the end of the batch instead, so it is used
  only where there is no key (mode changes from the menu, deactivation).
- Each composed syllable is STARTED, CHANGED (unconfirmed) ..., then CHANGED
  (confirmed) + STOPPED when it is done. A key that finishes one syllable and
  starts the next sends both in one batch.
- The first CHANGED a key causes carries `koreanime:key = true`, the others
  `false`. R Chromium dispatches one keydown "Process" (keyCode 229) per
  `true`, so each consumed key is one keydown, as on other systems.
- Views that are not B_INPUT_METHOD_AWARE (Terminal, ...) would get
  input_server's bottom-line window. Every composition event is marked
  `be:inline_only`, which input_server drops for such views
  (`InputServer::_MethodizeEvents`), and next to it goes a "direct" event:
  CHANGED, confirmed, `be:inline_only`, `koreanime:direct`, no `be:string`,
  with a B_KEY_DOWN in `be:translated` -- the syllable, or Backspace. Such
  views get only those key presses: the syllable typed, then Backspace and
  the new one each time it changes (`fShown`). Aware views get the direct
  events themselves and pass over them: BTextView needs `be:string`, R
  Chromium skips `koreanime:direct`. A mouse click commits, as the caret may
  move.
- The Deskbar replicant puts a new icon into its menu but keeps drawing the
  old one (`MethodReplicant::UpdateMethodIcon` does not invalidate), so a
  mode change selects the method again by its cookie, which repaints it.
- `be:reply_to` is a looper of the method's own; views send it
  B_INPUT_METHOD_STOPPED to drop a composition (BTextView on a click, R
  Chromium on a focus change), and the composer resets.
- input_server offers no call to make a method active, so a thread sends
  'MRsm' (what the Deskbar menu sends) for each method cookie from 2 on until
  `MethodActivated(true)` says it was this one. The keymap method is cookie 1.
- Toggles: B_HANGUL_KEY (key 0xf0, Korean keyboards), a right-Alt tap (right
  Command with RenkuOS's PC layout, pressed and released with nothing else),
  Shift+Space. Alt+Space stays input_server's own method switch.

## Browser side

R Chromium used `InputMethodMinimal`, which has no composition at all. The
change adds `InputMethodHaiku` and makes the content view B_INPUT_METHOD_AWARE:

- 114 (rchromium-native-x86): `chromium114_port/files/haiku_port/ozone/`
  `haiku_input_method.*`, `haiku_ime_event.h`; the view forwards
  B_INPUT_METHOD_EVENT to the UI thread.
- 154 (rchromium-native-x86_64, -arm64): the BView lives in the gcc-built
  shim, so `haiku_shim.h` gains `Delegate::OnInputMethod()` and
  `NativeWindow::CancelInputMethodWindow()` (appended, the shim and Chromium
  are rebuilt together), and `port/files/ozone/haiku/haiku_input_method.*`.

## HanBe, 2026-11-07

HanBe (`HanBe_x86`, a Korean input method installed by hand in
`~/config/non-packaged/add-ons/input_server/methods`) showed up beside this
one. Moving its file away while input_server runs makes input_server unload
it, and `HanBe::~HanBe` frees memory twice: input_server stops in the
debugger ("double free", stack through `_UnregisterAddOn`) and keyboard and
mouse die until a reboot. It looked like a kernel panic on the VAIO. The
post-install script therefore freezes input_server (SIGSTOP), moves HanBe*
to `~/config/settings/koreanime/disabled`, and kills it (SIGKILL, no
destructors); app_server relaunches input_server when its event stream
closes, and koreanime activates itself again. Tested on the VAIO with HanBe
loaded: no crash, input_server back within seconds.
